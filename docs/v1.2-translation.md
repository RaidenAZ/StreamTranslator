# StreamTranslator V1.2 Translation Subtitle Specification

状态：Accepted，等待实施

更新时间：2026-07-14

本文档固化 V1.2 翻译字幕 grilling 会话达成的产品、架构和实施共识。协议细节见 [v1.2-translation-protocol.md](v1.2-translation-protocol.md)，测试与验收见 [v1.2-translation-test-plan.md](v1.2-translation-test-plan.md)。

## Goals

V1.2 在不改变 V1.0/V1.1 音频捕获、VAD、分段和 MiMo ASR 主链路的前提下，为 final/final-ish 原文字幕增加低延迟双语翻译。

核心目标：

- 同时支持远程 API 和用户自行管理的本地模型服务。
- 只依赖 OpenAI Chat Completions compatible 协议。
- 原文字幕不被翻译延迟或翻译故障阻塞。
- 翻译结果与 V1.1 subtitle revision 保持一致。
- 悬浮窗和字幕历史稳定呈现双语内容。
- 保持进程、服务、队列、历史和错误状态可诊断。
- 对第三方模型保持协议兼容，但只对明确验收过的参考链路作质量承诺。

## Non-Goals

V1.2 不做：

- Anthropic Messages 或其他非 Chat Completions 协议。
- rolling interim ASR；该能力移到 V1.3 重新设计。
- 流式译文显示。
- 多字幕批量翻译。
- 自动模型发现或 `/v1/models` 下拉列表。
- 自动故障转移到其他模型配置。
- 应用层翻译结果缓存。
- 用户术语表；该能力明确不进入后续路线图。
- 用户自定义翻译 Prompt。
- 历史字幕自动补翻或离线批量重译。
- 运行中切换模型、目标语言或翻译开关。
- 自定义 HTTP Header、代理、Azure OpenAI 特殊协议或跳过 TLS 验证。
- 由 StreamTranslator 启动、停止或管理 vLLM、Ollama、llama.cpp、LM Studio 等模型服务。

## Supported Languages

翻译源语言继承 ASR 设置：

- `zh`：明确中文。
- `en`：明确英语。
- `auto`：翻译层根据字幕文本进行保守的中英文判断；无法确定时交给模型处理。

V1.2 目标语言：

| UI 名称 | 内部代码 | 验收级别 |
|---|---|---|
| 中文 | `zh-Hans` | 完整人工质量验收 |
| 英语 | `en` | 完整人工质量验收 |
| 德语 | `de` | 真实 API 最小 smoke |
| 法语 | `fr` | 真实 API 最小 smoke |
| 日语 | `ja` | 真实 API 最小 smoke |

“中文”固定表示简体中文，不使用含糊的 `zh`，V1.2 不提供繁体中文目标语言。

## User-Visible Behavior

### Translation Timing

原文和译文采用不同的显示时机：

1. ASR 原文完成本地 suffix/prefix 去重后立即显示。
2. C# 将当前字幕组提交给 translation worker。
3. translation worker 使用非流式 Chat Completions 请求。
4. 完整译文返回后，在原文下方一次性显示。
5. 翻译失败、超时或被丢弃时保留原文。

不等待译文后再显示原文，也不展示半句译文或 token 增量。

该体验属于重点验证项。实施后必须测试不同翻译延迟下的阅读割裂、空白译文区域和布局稳定性。

### Revision-Aware Translation

每个翻译任务绑定：

```text
utteranceGroupId + sourceRevision + targetLanguage + profileId
```

V1.1 产生 subtitle revision 时：

- 最新合并原文立即替换旧原文。
- 旧译文立即从物化 UI 中移除，因为它不再对应最新原文。
- 尚未发送的旧翻译任务取消。
- 已经发送的旧请求允许结束，但返回结果标记为 stale 并丢弃。
- 对最新合并原文发起新的独立翻译请求。
- 新译文完整返回后一次性显示。
- 旧翻译事件仍保留在 append-only 历史和诊断数据中。

revision 重译会增加翻译模型调用次数，但不得增加 MiMo ASR 调用次数。

### Out-Of-Order Results

译文独立填充自己的字幕组，不等待前序翻译：

- 原文顺序始终由 ASR sequence 决定。
- 后一条译文先返回时可以先显示。
- 译文完成时间不改变字幕历史排序。
- 已经离开悬浮窗的字幕不得因迟到译文重新出现。
- 未过期的迟到译文仍可写入字幕历史。

## Same-Language Skip

能够确定源语言与目标语言相同时，不调用翻译模型。

明确语言：

- ASR 为 `zh` 且目标为 `zh-Hans`：跳过。
- ASR 为 `en` 且目标为 `en`：跳过。

`auto` 模式只做轻量、确定性的中英文字符判断：

- 明显以 CJK 汉字为主时判为中文。
- 明显以拉丁字母为主时判为英文。
- 中英混合、纯数字、短专有名词或低置信文本视为未知，继续请求翻译。
- 不引入 PyTorch、语言检测模型或额外远程请求。

跳过事件记录为 `translation_skipped_same_language`，普通 UI 只显示原文。

该策略属于重点风险项。中英混合、代码切换、专有名词和极短字幕必须进入专项测试，错误隐藏有效译文次数必须为 0。

## Translation Context

翻译请求附带有限滚动上下文：

- 最多最近 3 个稳定字幕组。
- 每个上下文项最多保留 30 秒。
- 提供原文和可用的最终译文。
- 当前原文是唯一需要翻译的内容。
- Prompt 明确禁止重新输出、修改或翻译上下文。

上下文清理规则：

- 新捕获会话开始时清空。
- 停止字幕时清空。
- 目标语言变更时清空。
- subtitle revision 使用最新原文替换同组上下文，不清空其他有效项。
- 模型配置变更只能发生在会话停止后；下一会话不携带旧模型生成的译文上下文。
- 超过 30 秒的上下文项自动失效。

不发送整场字幕历史，也不发送音频给翻译服务。

## Translation Profiles

V1.2 支持多个命名模型配置，同时只能激活一个。

配置字段：

| 字段 | 要求 |
|---|---|
| `id` | 稳定 GUID，不随名称修改 |
| `name` | 用户可读名称 |
| `baseUrl` | Chat Completions API 根地址，包含服务要求的路径前缀 |
| `model` | 用户手动填写模型名 |
| `apiKey` | 可为空，明文保存，沿用现有安全决策 |
| `location` | `Local` 或 `Remote`，应用提供自动建议，用户最终确认 |
| `requestCompatibility` | `Standard`、`DeepSeek`、`QwenVllm` 或 `Custom` |
| `customExtraBody` | 仅自定义模板使用的 JSON object |
| `timeoutMs` | 3000-30000，默认 10000 |
| `maxConcurrency` | 1-4，默认 2 |

用户可以添加、编辑、复制、删除、测试和选择配置。V1.2 不自动切换配置，也不根据 URL 或模型名猜测品牌。

### Local And Remote Classification

应用根据地址提供初始建议：

- localhost、loopback 和私有局域网 IP 建议为 `Local`。
- 公网 IP 和域名建议为 `Remote`。
- 用户可以修改分类。
- 分类只影响 UI、HTTPS 校验、诊断标签和静态数据发送说明，不改变协议实现。

远程配置必须使用 HTTPS。本地配置允许 HTTP。V1.2 不提供忽略不安全远程连接或跳过证书校验的选项。

远程配置页面显示非阻塞说明：

```text
当前字幕及近期上下文将发送到此 API 地址。
```

不显示隐私确认弹窗，也不保存隐私确认状态。

### Base URL Rules

OpenAI Python SDK 不自动添加 `/v1`。应用也不得自动添加或删除 `/v1`。

URL 规则：

- 用户填写完整 Base URL 路径前缀。
- 应用只规范化末尾 `/`。
- worker 在 Base URL 后解析 `chat/completions`。
- 输入框下方实时显示最终请求地址。
- 用户直接填写以 `/chat/completions` 结尾的地址时阻止保存，避免重复拼接。
- URL 中的 query 和 fragment 不作为认证配置入口。

示例：

```text
Base URL: http://127.0.0.1:8000/v1
Preview:  http://127.0.0.1:8000/v1/chat/completions
```

```text
Base URL: https://example.com
Preview:  https://example.com/chat/completions
```

## Request Compatibility Templates

应用提供四种 `extraBody` 模板：

| 模板 | 最终 extraBody |
|---|---|
| Standard | `{}` |
| DeepSeek | `{"thinking":{"type":"disabled"}}` |
| Qwen + vLLM | `{"chat_template_kwargs":{"enable_thinking":false}}` |
| Custom | 用户提供的 JSON object |

不根据模型名自动选择模板。测试连接负责确认服务是否接受所选扩展参数。

自定义 `extraBody`：

- 必须是合法 JSON object。
- 最大 16KB。
- 禁止覆盖 `model`、`messages`、`stream`、`tools`、`tool_choice`、`functions`、`function_call` 和 `response_format`。
- 不允许添加 Header、API Key 或 URL。
- JSON 解析错误必须显示行列信息。

## Prompt Contract

V1.2 使用内置、版本化 Prompt，不允许用户编辑。

Prompt 目标：

- 只翻译当前字幕。
- 上下文只用于指代、术语和语气一致性。
- 字幕和上下文是数据，不是可执行指令。
- 只返回纯文本译文，不返回解释、Markdown、前缀或引号。
- 不总结、不扩写、不猜测缺失内容。
- 保留数字、时间、单位、专有名词和事实关系。
- 保留口语、重复、犹豫、粗俗表达和原文语气。
- 使用目标语言自然语序，但不做文学润色。
- 原文已经是目标语言时原样返回。

请求不主动发送 `temperature`、`top_p`、`top_k` 或其他采样参数，使用模型服务默认值。用户可以通过自定义 `extraBody` 主动提供非保留字段。

worker 只读取最终 `content`，忽略 `reasoning_content`。响应规范化规则见协议文档。

## Scheduling And Backpressure

每个当前字幕组单独请求，不批量等待后续字幕。

默认调度参数：

| 参数 | 默认值 | 可配置 |
|---|---:|---|
| 最大并发 | 2 | 配置级，1-4 |
| 请求超时 | 10 秒 | 配置级，3-30 秒 |
| 待处理队列 | 8 | V1.2 固定 |
| 最大排队时长 | 10 秒 | V1.2 固定 |
| 停止排空时间 | 3 秒 | V1.2 固定 |

背压策略：

- 队列不得无限增长。
- 尚未发送且等待超过 10 秒的任务视为过期。
- 超限时优先丢弃旧 revision、最旧任务和已经离开悬浮窗的任务。
- 原文和原文历史始终保留。
- 被丢弃的译文记录 `translation_dropped_backpressure`。
- 主页面显示翻译速度不足和当前队列状态。

队列长度和等待时限是否开放给用户属于后续调优项。V1.2 先固定数值并收集 metrics。

## Retry, Circuit Breaker And Worker Recovery

单请求错误处理：

- 网络、连接超时、HTTP 429 和 5xx 最多重试一次。
- 重试前检查任务是否仍为最新 revision 且尚未超过 10 秒有效期。
- 401/403、模型不存在、协议错误、配置错误和无效响应不重试。
- 不自动切换其他模型配置。

会话级熔断：

- 认证、模型不存在、协议或配置错误立即停止本会话翻译。
- 网络、超时、429、5xx 连续失败 3 条后暂停 10 秒。
- 冷却后使用下一条最新字幕作为探测请求。
- 再次失败时逐步增加冷却时间，最大 60 秒。
- 探测成功后恢复并清零连续失败计数。
- 停止字幕后清空熔断状态。

translation worker 进程恢复：

- 每个捕获会话最多自动重启一次。
- 已发送但未返回的请求不重新提交，避免重复费用。
- 未发送且仍有效的任务可以在 worker 恢复后继续处理。
- 第二次崩溃时停止本会话翻译，ASR 继续运行。

## Session Lifecycle

translation worker 跟随捕获会话：

```text
翻译关闭:
  不启动 translation worker

开始字幕且翻译开启:
  启动 asr_worker
  启动 translation_worker
  固定本会话翻译配置
  启动音频捕获

停止字幕:
  停止产生新任务
  最多等待 3 秒完成已有译文
  取消剩余任务
  shutdown translation_worker

关闭主窗口:
  短暂优雅关闭
  超时后 Kill entire process tree
```

运行期间禁止：

- 开启或关闭翻译。
- 切换活动配置。
- 修改活动配置。
- 切换目标语言。
- 修改请求兼容模板、超时或并发数。

本地模型服务由用户管理，StreamTranslator 关闭时不得终止用户的 vLLM、Ollama、llama.cpp 或 LM Studio 进程。

## Startup And Connection Testing

新建或修改关键配置后，配置状态变为未验证。

“测试连接”使用临时 translation worker，发送一条真实、极短的 Chat Completions 请求：

- 目标为中文、德语、法语或日语：`The live stream starts at 9:30.`
- 目标为英语：`直播将在9:30开始。`

不要求译文与固定答案完全匹配。成功标准是：

- URL 可访问。
- 鉴权通过。
- 模型存在。
- 请求结构兼容。
- `choices[0].message.content` 可解析且非空。
- 响应未超过限制并在超时内完成。

测试结果显示：

- 测试原文。
- 规范化后的模型返回。
- 请求耗时。
- 成功、警告或分类错误。

常见警告：

- 输出与明确不同语言的原文完全相同。
- 包含多余包装、Markdown 或 `Translation:` 前缀。
- 出现 `<think>` 或 `reasoning_content`。
- 输出长度明显异常。

配置验证结果绑定配置指纹。Base URL、模型、API Key、兼容模板或自定义 `extraBody` 修改后使验证失效。每次开始字幕不重复发送测试文本。

翻译配置未验证或 worker 启动失败时，不阻止 ASR。应用提示用户选择“仅启动原文字幕”或返回设置。运行中翻译故障不弹阻塞对话框。

## Settings Schema V3

建议配置形状：

```json
{
  "schemaVersion": 3,
  "translation": {
    "enabled": false,
    "targetLanguage": "zh-Hans",
    "activeProfileId": null,
    "profiles": [
      {
        "id": "9a7a57da-5c95-4e44-9e3b-54795ae90998",
        "name": "DeepSeek API",
        "baseUrl": "https://example.com/v1",
        "model": "model-name",
        "apiKey": "",
        "location": "Remote",
        "requestCompatibility": "DeepSeek",
        "customExtraBody": {},
        "timeoutMs": 10000,
        "maxConcurrency": 2,
        "validationFingerprint": null,
        "lastValidatedAt": null,
        "lastValidationLatencyMs": null
      }
    ]
  },
  "subtitleWindow": {
    "fontSize": 18,
    "maxSubtitleItems": 2,
    "opacity": 0.72,
    "clickThroughWhenLocked": true
  }
}
```

默认值：

- 翻译关闭。
- 目标语言为简体中文。
- 不创建默认模型配置。
- 没有活动配置时，翻译按关闭处理。
- 请求兼容模板默认 Standard。
- 超时 10 秒，并发 2。
- 悬浮窗字号 18，显示字幕数 2。

V1.2 配置迁移采用强制规则：

- 所有旧配置的悬浮窗字号直接覆盖为 18，不保留旧值。
- `MaxLines` 迁移为 `MaxSubtitleItems`，数值保持并限制在 1-3。
- 翻译配置默认关闭且配置列表为空。
- 不弹出迁移确认。

## Main Window UI

翻译配置继续放在现有设置页，不新增导航项。

翻译分组位置：识别服务与悬浮窗设置之间。

默认页面只暴露：

- 翻译总开关。
- 目标语言。
- 活动模型配置。
- 配置验证状态。
- 测试连接。

模型配置使用 Fluent 可选择项呈现，延续 VAD 模式切换的清晰选中状态。配置超过一行时向下换行，不使用横向滚动。添加和编辑使用 ContentDialog，高级字段默认折叠。

UI 设计要求：

- 避免把所有 URL、Key 和 JSON 输入框长期暴露在设置页。
- 不创建嵌套卡片。
- 使用 WPF-UI、Fluent Design、系统主题和 Mica 既有风格。
- 添加、编辑、复制、删除和测试使用合适的图标按钮和工具提示。
- 删除活动配置需要确认。
- 捕获运行期间整个翻译分组只读。

主页“运行链路”扩展为：

- 音频输入。
- 语音检测。
- 识别进程。
- 识别接口。
- 翻译进程。
- 翻译接口。
- 字幕输出。

翻译关闭显示“已关闭”，不是错误。worker 正常但模型请求失败时，翻译进程与翻译接口必须分别显示状态。

## Floating Subtitle Window

悬浮窗从单个 TextBlock 改为字幕组列表。

每个字幕组：

- 原文在上，使用用户字号。
- 译文在下，默认使用原文字号的 90%。
- 译文颜色或不透明度略弱，但保持可访问对比度。
- 原文和译文都自动换行。
- 不显示时间、错误文本、加载图标或目标语言标签。

布局规则：

- 默认原文字号强制迁移为 18。
- “最大行数”改名为“显示字幕数”，范围 1-3，默认 2。
- 每个双语字幕组按一个字幕条目计算。
- 翻译处理中只预留基础译文高度。
- 翻译跳过或失败后折叠空白区域。
- 窗口可随内容增高，但不超过当前屏幕工作区高度的 40%。
- 超高时优先移除最旧字幕组，保证最新字幕完整可读。
- 已离开悬浮窗的字幕不得因迟到译文重新出现。

## Subtitle History

历史显示：

```text
01:23:45  Hello!
          你好

01:23:47  My name is John.
          我的名字叫约翰
```

规则：

- 时间使用原文 `GeneratedAt`，不显示译文完成时间。
- 原文和译文共用内容列。
- 译文自动换行。
- 无论是否跨天或切换目标语言，都不显示语言标签。
- 没有译文时只显示原文。
- 不自动补翻旧历史。

现有复制功能默认复制可用双语内容：

- 复制选中。
- 复制最近 10 条。
- 复制当天全部。

没有译文的条目只复制原文。V1.2 不增加仅原文、仅译文和双语三种复制模式。

## Append-Only Translation History

翻译不得原地改写原始 subtitle 或 subtitle_revision 事件。

成功译文追加 `translation_result`：

```json
{
  "type": "translation_result",
  "utteranceGroupId": "20260714-120000-a1b2:42",
  "sourceRevision": 2,
  "targetLanguage": "zh-Hans",
  "translatedText": "我的名字叫约翰。",
  "translationProfileId": "9a7a57da-5c95-4e44-9e3b-54795ae90998",
  "model": "model-name",
  "completedAt": "2026-07-14T12:00:04.123+08:00"
}
```

失败、过期、跳过和背压丢弃可以追加不含译文的 `translation_status` 事件，用于诊断和恢复状态。普通历史 UI 不显示错误文本。

历史物化：

1. 先按 V1.1 规则物化每个 utterance group 的最新 source revision。
2. 只选择与当前 source revision 匹配的最新成功 `translation_result`。
3. 旧 source revision 的译文不得覆盖新原文。
4. 旧版没有翻译事件的记录按 source-only 兼容读取。

历史和诊断数据不得保存 API Key、Authorization Header 或未脱敏认证参数。

## Diagnostics And Metrics

轻量 metrics 始终记录，不包含字幕文本：

- 请求、成功、失败和重试数。
- revision 重译次数。
- stale result、同语言跳过和背压丢弃数。
- 队列当前值和峰值。
- translation worker 重启数。
- 熔断次数和冷却时长。
- 延迟 P50/P95。
- 模型名、本地/远程类型和目标语言。
- API usage；只有服务返回时记录 token 数。

诊断模式开启时额外写入 `data/debug-translation/`：

- 当前原文和最近上下文。
- 目标语言和 Prompt 版本。
- 最终译文。
- source revision 和任务标识。
- 开始、完成和排队时间。
- 脱敏后的最终请求地址。
- 错误分类和经过长度限制的响应摘要。

始终不保存 API Key、Authorization Header、完整原始 HTTP Header、无限制服务端响应或 worker 环境变量。

## Offline Evaluation

V1.2 提供 `scripts/translation-evaluate.ps1`，直接读取固定文本样本，不经过音频和 MiMo ASR。

目标：

- 复用正式 translation worker、Prompt 和响应规范化逻辑。
- 输出原文、译文、延迟、错误、usage 和 warning。
- 汇总 P50/P95、失败率、格式异常率和 revision 重译统计。
- 只有显式 `-AllowLiveApi` 时允许真实 API 请求。

离线评估脚本的 API Key 提供方式尚未最终确认，必须在实施脚本前单独决定。不得默认把 Key 写入命令行参数、样本或结果文件。

## Initial Acceptance Gates

DeepSeek V4 Flash 远程参考链路初始延迟门槛：

模型标识仍由用户手动填写，并在验收记录中保存实际使用值；应用不硬编码模型名。

- P50 不超过 1.5 秒。
- P95 不超过 3 秒。
- C# 排队、worker 通信和 UI 更新合计 P95 不超过 100ms。

该门槛是首轮测试目标，不是永久标准。若真实测试持续不能满足，需要基于数据细化。

中英文人工质量验收：

- 英译中和中译英各至少 50 条。
- 严重错误率低于 5%。
- 数字、时间和单位错误率低于 2%。
- 多余解释、Markdown、思考文本或空译文低于 1%。
- 旧 revision 误覆盖次数为 0。
- 同语言判断错误隐藏有效译文次数为 0。

德语、法语和日语各执行一次真实 DeepSeek 最小 smoke。完整测试矩阵见 [v1.2-translation-test-plan.md](v1.2-translation-test-plan.md)。

## Implementation Order

建议按以下顺序实施：

1. 配置模型、schema v3 迁移和验证器。
2. Python translation worker、Prompt builder、兼容模板和 fake HTTP 测试。
3. C# worker client、队列、上下文、重试、熔断和进程恢复。
4. translation history events 和物化逻辑。
5. 设置页模型配置管理和测试连接。
6. 主页状态、悬浮双语字幕和历史双语展示。
7. 离线评估脚本和完整自动测试。
8. DeepSeek 真实验收、本地手工测试、UI smoke 和发布包验证。

## Deferred And Open Items

后续评估：

- 队列长度和最大等待时长是否开放给用户。
- 非流式译文后补的实际阅读体验。
- `auto` 同语言判断阈值和代码切换表现。
- DeepSeek 延迟门槛是否需要调整。
- 离线评估脚本的 API Key 提供方式。
- 其他模型服务的 `extraBody` 兼容模板。

明确延期：

- rolling interim ASR：V1.3。
- 本地模型真实验收：用户手工执行，不阻塞 V1.2 发布。
