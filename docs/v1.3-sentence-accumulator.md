# StreamTranslator V1.3 — Sentence-Level Translation Grouping

## Overview

V1.2 segments audio by time (VAD endpoint or `hardMaxSegmentMs`), sends each segment to ASR
independently, and translates each segment independently. When the speaker talks continuously
without natural pauses, `hardMax` cuts produce transcripts that begin mid-sentence with no prior
context. This causes confusing translations and a fragmented history view.

This spec introduces `TextSentenceAccumulator`, a component that buffers ASR output across
`hardMax` boundaries and flushes semantically complete sentences as translation units.

Floating-window real-time display is **unchanged**. History and translation are the two surfaces
that benefit.

---

## Problem Statement

Observed in a continuous-speech session (game reveal stream, 2026-08-04):

| Segment | CutReason | Source text (truncated) |
|---|---|---|
| Seq 1 | SilenceDetected | "…Train Sim World Six will be coming on September 2025." |
| Seq 2 | HardMax | "**Five**, coming with a top-notch selection…" |
| Seq 3 | HardMax | "**The free starter edition.** So the free starter pack…" |
| Seq 4 | HardMax | "Train Sim World Journey. …**The free start.**" |
| Seq 5 | HardMax | "**The free starter pack** will be available…" |

Each segment is translated in isolation. "Five," has no context; "The free start." is a
mid-sentence truncation. The translation model cannot recover semantic continuity.

The **ASR accuracy problem** (each chunk transcribed without audio context from prior chunks)
requires streaming ASR and is deferred. This spec addresses the **translation unit problem**
and **history coherence problem**, both fixable at the text layer.

---

## Design Goals

1. History view shows sentence-complete entries instead of time-aligned fragments.
2. Translation input spans one or more `hardMax` segments and ends at a sentence boundary.
3. Floating window real-time display is unchanged (all ASR segments shown immediately).
4. No new ML model dependencies; sentence detection uses punctuation heuristics.
5. Force-flush threshold is user-configurable (default 350 chars, range 50–800).
6. Source-language tail of the previous sentence unit is passed to the translation model as
   context (implements the "prior source context" improvement discussed during design).

## Non-Goals

- Fixing ASR transcription accuracy at segment boundaries — requires streaming ASR (WebSocket);
  deferred pending a cost-effective API. `TextSentenceAccumulator` remains useful even when
  streaming ASR is added, as a fallback for segments that still need grouping.
- Speaker change detection (Layer 2); deferred to a later V1.3 iteration.
- ML-based punctuation restoration (e.g. `deepmultilingualpunctuation`); can replace the regex
  heuristic in a future patch without changing the accumulator contract.
- Streaming translation display.

## Architecture

### Current flow

```
SubtitleRuntime
  └─ OnSubtitleReady(item)
       ├─ FloatingSubtitleWindow.PublishSource(item)   // real-time display
       ├─ SubtitleList.Items.Insert(0, item)            // history UI
       ├─ SubtitleHistoryStore.AppendAsync(item)        // persistence
       └─ TranslationSession.Submit(item)               // translation
```

### New flow

```
SubtitleRuntime
  └─ OnSubtitleReady(item)
       ├─ FloatingSubtitleWindow.PublishSource(item)     // UNCHANGED — real-time
       └─ TextSentenceAccumulator.Add(item)
              │  (on SentenceUnitReady)
              ├─ SubtitleList.Items.Insert(0, unit)       // history UI — sentence units only
              ├─ SubtitleHistoryStore.AppendAsync(unit)   // persistence — sentence units only
              └─ TranslationSession.Submit(unit)          // translation — sentence units only
```

`TextSentenceAccumulator` raises `SentenceUnitReady` when it decides a complete translation
unit is ready. The history list and translation session are now driven by this event, not by
raw `SubtitleReady`.

## CutReason Propagation

`CompletedSpeechSegment.CutReason` exists today but is not forwarded to `SubtitleItem`.
It must be added so the accumulator can distinguish forced from natural boundaries.

Add to `SubtitleItem` (Core project):

```csharp
public string? CutReason { get; init; }
// Values: "SilenceDetected" | "SoftMax" | "HardMax" | null (legacy/unknown)
```

Set it in `SubtitleRuntime.PublishTerminalResponseAsync` when constructing the `SubtitleItem`,
forwarding `segment.CutReason.ToString()`.

Accumulator flush rules by CutReason:

| CutReason | Accumulator action |
|---|---|
| `SilenceDetected` | Flush immediately — natural speech boundary |
| `SoftMax` | Flush immediately — soft segment limit with some silence |
| `HardMax` | Accumulate; apply sentence boundary check |
| `null` / unknown | Flush immediately (safe default) |

## TextSentenceAccumulator

### Responsibilities

- Receive `SubtitleItem` instances from `SubtitleRuntime`.
- Buffer items whose `CutReason` is `HardMax`.
- Detect sentence boundaries in the accumulated text.
- Emit `SentenceUnit` events representing semantically complete translation units.
- Force-flush when the buffer exceeds the configured character threshold.

### State

```csharp
private readonly List<SubtitleItem> _buffer = [];
private string _previousSentenceSourceTail = "";  // context for translation
private int ForceFlushThreshold => _settings.Translation.SentenceAccumulationLimit;
```

### Processing algorithm

```
Add(item):
  1. Append item to _buffer.
  2. If item.CutReason is NOT HardMax  →  Flush("natural")
  3. Else:
       combinedText = string.Join(" ", _buffer.Select(x => x.SourceText))
       boundary = SentenceBoundaryScanner.FindLast(combinedText)
       if boundary found:
           sentenceText  = combinedText[..boundary]
           remainderText = combinedText[boundary..].TrimStart()
           Flush("sentence", upTo: boundary)
           RetainRemainder(remainderText)
       else if combinedText.Length >= ForceFlushThreshold:
           Flush("force")
```

### Flush output — SentenceUnit

```csharp
public sealed record SentenceUnit
{
    public string SourceText { get; init; }          // combined sentence text
    public TimeSpan Start    { get; init; }          // earliest contributing segment
    public TimeSpan End      { get; init; }          // latest contributing segment
    public DateTimeOffset GeneratedAt { get; init; } // latest timestamp
    public string UtteranceGroupId { get; init; }    // last contributing group id
    public string[] ContributingGroupIds { get; init; }
    public string PreviousSentenceSourceTail { get; init; } // last ~100 chars of prior unit
    public string FlushReason { get; init; }         // "natural"|"sentence"|"force"
}
```

`SentenceUnit` is converted to a regular `SubtitleItem` (with `Type = "sentence_unit"`)
before being passed to history and translation — no schema changes to downstream consumers.

### Remainder attribution after sentence split

When a sentence boundary splits a buffer item's text (the boundary falls inside one item's
`SourceText`), that item is partially consumed. The implementation:

1. Remove all items whose full text is consumed by `sentenceText`.
2. Trim the last partially-consumed item's `SourceText` to the remainder slice.
3. Keep it in the buffer as the first item of the next accumulation cycle.

This approximation is acceptable because partial items are short tail fragments that gain
full context in the next sentence.

## Sentence Boundary Detection

`SentenceBoundaryScanner` is a static helper in the Core project.

### Algorithm

```
FindLast(text):
  candidates = all matches of regex [.!?][ \t]+[A-Z]  (position of the space/tab)
  for each candidate (right to left):
      wordBefore = last word ending at the punctuation mark
      if wordBefore.Length <= 2            → skip (abbreviation: "Mr.", "St.")
      if wordsInSentence(text, candidate) < MinSentenceWords (default 5) → skip
      return candidate position
  return -1  (no boundary)
```

### Known limitations (acceptable for V1.3)

- Decimal numbers ("9.30") and URLs are treated as sentence ends if followed by a capital
  word. False positive rate is low in conversational English ASR output.
- Non-English source languages with different punctuation conventions are not handled.
  A punctuation restoration model can replace this scanner in a future patch without
  changing the accumulator contract.

## Settings Changes

### New setting: translation accumulation threshold

| Field | Value |
|---|---|
| Location | Settings page → 字幕翻译 card |
| Label | 翻译积累上限（字符） |
| Control | `NumberBox` |
| Range | 50 – 800 |
| SmallChange / LargeChange | 50 / 100 |
| Default | 350 |
| Caption | "积累更多内容再翻译可提升连贯性，但会增加翻译延迟。" |
| AppSettings path | `Translation.SentenceAccumulationLimit` (int) |

The setting participates in the existing auto-save debounce (800 ms) and is persisted in
`settings.json`. Schema version bumped to **5**.

### Schema migration

On load, if `schemaVersion < 5`, set `Translation.SentenceAccumulationLimit = 350`.

### Existing setting: hardMaxSegmentMs

Already present in Settings → 音频 → "最长片段 (ms)", `HardMaxSegmentBox`,
range 6 000 – 20 000 ms, default 10 000. No change needed.

## Display Model Changes

### Floating window

`FloatingSubtitleWindow` continues to receive `SubtitleReady` for every ASR segment.
No change. HardMax continuation fragments appear and are replaced in real time as usual.

**Pending-translation state for HardMax segments**: floating window entries that are
absorbed by the accumulator will never receive a `translatedText` update. In V1.3 this
gap is accepted — the floating window shows original-language text for those entries.
A future improvement could mark them with a visual "⌛" indicator.

### History list

`SubtitleList` is populated from `SentenceUnitReady` instead of `SubtitleReady`.
Each history entry corresponds to one complete sentence (or a force-flushed unit).
The view shows fewer but more coherent entries compared to V1.2.

### History persistence

`SubtitleHistoryStore` receives the `SentenceUnit`-derived `SubtitleItem`
(`type = "sentence_unit"`). The JSONL format is the same. V1.2 history files
(`type = "subtitle"`) continue to load and display correctly — no migration.

## Translation Context

When `TranslationSession.Submit` is called with a `SentenceUnit`-derived item:

- `sourceText` is the combined sentence text (unchanged field).
- The existing `context` list of recent translated entries is passed (unchanged).
- **New**: `PreviousSentenceSourceTail` (last ≤ 120 characters of the prior sentence unit's
  source text) is appended to the translation worker's prompt as a `previous_source` hint.

Translation worker prompt template gains an optional `previous_source` section:

```
[If previous_source is non-empty]
Previous transcript (source language, for context only — do not translate):
{previous_source}

Translate the following:
{source_text}
```

This is the "Option A" prior-source-context improvement scoped to sentence units, which is
more effective than per-segment context because the unit boundaries are now linguistically
meaningful.

## Test Considerations

### Unit tests — `SentenceBoundaryScanner`

- Full sentence ending with `. ` + capital → finds boundary.
- Abbreviation `"Mr. Smith"` → not a boundary.
- Sentence shorter than `MinSentenceWords` → not a boundary.
- Multiple sentences in text → returns last valid boundary.
- No boundary in text → returns -1.

### Unit tests — `TextSentenceAccumulator`

- Single item with `CutReason = SilenceDetected` → immediate flush, no buffer.
- Two HardMax items forming one complete sentence → flush on second item.
- Three HardMax items, sentence boundary in second → flush after second, third retained.
- Buffer exceeds `ForceFlushThreshold` without boundary → force flush.
- Remainder text carries into next cycle correctly.

### Integration

- `SubtitleItem.CutReason` is set for all three cut types in runtime tests.
- `SentenceAccumulationLimit` round-trips through settings save/load (schema v5 migration).

### Smoke test

Run `ui-store-shell-smoke.ps1` after the change. Verify:
- Floating window still shows real-time per-segment subtitles.
- History list entries are coherent sentences (manual inspection).
- No regression in subtitle copy / clear history flows.

## Open Items

1. **Floating window pending-translation indicator** — HardMax segments absorbed by the
   accumulator never get a `translatedText`. Consider a "⌛" visual marker in a follow-up.

2. **Non-English source language punctuation** — The regex scanner is tuned for English.
   If the source language is Chinese, Japanese, or Korean, sentence-ending characters differ
   (`。？！`). Extend `SentenceBoundaryScanner` when non-Latin source languages are added.

3. **Streaming ASR re-evaluation** — When a WebSocket-capable ASR API becomes cost-effective,
   `TextSentenceAccumulator` transitions from primary segmentation logic to a fallback for
   segments that still arrive as complete chunks. The component interface is unchanged.

4. **Speaker change detection (Layer 2)** — Provides an additional `SpeakerChange` flush
   signal to the accumulator. Deferred; no interface changes needed at this layer to add it.
