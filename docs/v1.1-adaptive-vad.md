# StreamTranslator V1.1 Adaptive VAD Specification

状态：Implemented，等待真实直播样本验收

本文档固化 2026-07-13 至 2026-07-14 grilling 会话达成的完整共识。它是 V1.1 自适应尾静音、字幕分组与历史修订功能的实现规格。若实现细节与本文冲突，以本文和 `decisions.md` 中对应的 Accepted 决策为准。

## Goals

V1.1 不尝试识别“体育、游戏、新闻、发布会”等内容类别，而是根据当前音频中近期真实停顿节奏，自适应调整尾静音端点。

核心目标：

- 普通用户只选择优化目标，不需要理解具体毫秒数。
- 在直播状态快速切换时，几次讲话内完成响应。
- 优先降低半句被切断的概率，同时限制额外等待。
- 保持算法确定、可离线回放、可单元测试。
- 不增加 MiMo ASR 调用次数。

## Non-Goals

V1.1 第一版不做：

- 按直播内容类别自动识别场景。
- 分析 ASR 文本、MiMo 返回内容或 LLM 语义。
- 动态调整 VAD threshold、`StartSpeechMs`、`MinSegmentMs` 等其他参数。
- 拼接 WAV 后重新调用 MiMo ASR。
- 保存跨会话学习状态。
- 滚动 interim ASR。

## User Modes

设置页提供四种断句策略：

| 模式 | 初始值 | 自适应范围 | 目标 |
|---|---:|---:|---|
| 低延迟 | 250ms | 200-400ms | 更快显示，允许更多字幕修订 |
| 均衡 | 400ms | 280-600ms | 默认模式，兼顾延迟与完整性 |
| 句子完整 | 600ms | 400-800ms | 演讲、新闻和长句优先 |
| 固定值 | 用户输入 | 200-800ms | 完全关闭自适应，保持 V1.0 行为 |

三个自适应模式只动态调整 `EndSilenceMs`。其他 VAD 和分段参数保持不变。

固定值模式仍观察 quick-resume 以生成对比 metrics，但不改变端点、不请求字幕合并，因此用户可见分段行为保持 V1.0 等价。

## Configuration And Rollout

V1.1 默认启用 `均衡` 自适应模式。

项目仍处于测试阶段，因此采用强制迁移：

- 新安装默认使用 `均衡`。
- 旧配置首次加载后也直接使用 `均衡`。
- 不把旧 `EndSilenceMs` 猜测为低延迟、均衡或句子完整。
- 不提供旧值恢复入口或迁移确认弹窗。
- 用户需要固定端点时，主动切换到 `固定值` 并填写 200-800ms。

建议配置形状：

```json
{
  "schemaVersion": 4,
  "asr": {
    "language": "auto"
  },
  "vad": {
    "endpointMode": "Balanced",
    "endSilenceMs": 400,
    "startSpeechMs": 96,
    "preRollMs": 192,
    "minSegmentMs": 900,
    "softBreakSilenceMs": 128,
    "softMaxSegmentMs": 4000,
    "hardMaxSegmentMs": 10000,
    "overlapMs": 600
  }
}
```

schema V4 在保留现有 VAD 模式的基础上增加两项产品约束：ASR 识别语言强制迁移为 `auto`；设置页开放 `HardMaxSegmentMs`，范围 6000-20000ms、默认 10000ms。`SoftMaxSegmentMs` 与 overlap 不开放。

`EndSilenceMs` 在固定值模式中是用户值，在自适应模式中仅作为持久化占位，不代表当前动态端点。当前值由运行时控制器输出。

## Adaptive Endpoint Controller

新增 C# 独立模块 `AdaptiveEndpointController`，位于 VAD 决策与 `SpeechSegmenter` 之间。

控制器只允许读取：

- VAD speech/non-speech 决策与单调时间戳。
- 当前片段是否因尾静音切断。
- 切断后下一次确认语音的时间。
- 当前模式、动态端点和模式边界。

控制器不读取：

- 原始音频内容。
- ASR 文本或 MiMo 返回内容。
- LLM 语义。
- 直播类别。

控制器输出：

- `EffectiveEndSilenceMs`。
- 相邻片段是否归入同一个 `utteranceGroup`。
- 调整原因和轻量 metrics。

## Learning Window

学习窗口按事件数量和样本时效共同限制：

- 最多保留最近 8 次有效停顿。
- 样本最长保留 15 秒，过期即丢弃。
- 至少积累 3 次有效停顿后才开始自适应。
- 新停顿自然占据窗口，因此场景变化后约 3-5 次讲话即可完成响应。
- 连续 10 秒没有确认语音时清空停顿样本。
- 空闲后端点按每次 25ms、受正常冷却约束，逐步回归模式初始值，不瞬间跳回。

## Pause Signals

有效停顿包括：

1. 片段内部 speech 到 non-speech，再恢复 speech 的完整停顿。
2. 因尾静音切段后，到下一次确认 speech 的完整停顿。

第二类停顿计算：

```text
完整停顿 = 切段时的 EffectiveEndSilenceMs + 切段后到确认语音恢复的时间
```

完整停顿不超过 800ms 时，视为疑似过早切段：

- 纳入后续端点学习。
- 可触发相邻字幕归入同一个 `utteranceGroup`。
- 不撤回已发送的 ASR 请求。

超过 800ms 的恢复视为正常句间停顿，不触发误切上调或字幕合并。

## Adjustment Algorithm

目标端点参考最近有效停顿的 P75，再增加 50ms 安全余量，并限制在当前模式范围内。

采用非对称调整：

- 连续出现 2 次疑似过早切段后，每次上调 50ms。
- 至少有 6 个有效停顿、且近期没有疑似误切时，才允许下调。
- 每次下调 25ms。
- 两次调整至少间隔 2 秒。
- 任意滚动 10 秒内最多调整 2 次。
- 固定值模式不执行任何学习或调整。

端点过短会直接破坏句子；端点略长通常只增加几十毫秒等待。因此上调恢复完整性的速度高于下调追求低延迟的速度。

## Utterance Grouping

疑似误切只做字幕层合并，不做音频层重识别。

规则：

- 第一个 ASR 结果立即显示，不等待后续片段。
- 完整停顿不超过 800ms 时，相邻 sequence 可归入同一 `utteranceGroup`。
- `utteranceGroupId` 带捕获会话唯一前缀，避免同一天多次启停后 sequence 从 1 重置造成历史冲突。
- 允许有限链式合并，最多 3 个 ASR 片段。
- 同组音频时间跨度最多 12 秒。
- 只能合并相邻 sequence，不能跨过其他字幕。
- 任一间隔超限、ASR 失败、片段数达到 3 或跨度达到 12 秒时关闭当前组。
- 使用现有本地确定性 suffix/prefix 去重合并文本。
- 不新增第三次 ASR 请求，不依赖 LLM。

## UI Revision Behavior

字幕修订对普通用户静默发生：

- 后续片段返回后，主窗口历史更新同一行，不新增重复行。
- 如果该组仍是悬浮窗当前字幕，则替换为合并后的文本。
- 已经滚出当前悬浮窗的旧字幕不重新弹回，只更新历史记录。
- 不显示“临时字幕”“修订中”等标签。
- 修订次数、原始 sequence 和合并原因只进入诊断与历史事件。

设置页显示：

```text
断句策略: 低延迟 / 均衡 / 句子完整 / 固定值
当前断句等待: 425ms（均衡，自适应）
```

只有固定值模式启用 200-800ms 数字输入。

## Append-Only History Revisions

字幕历史继续使用 `data/subtitles/YYYY-MM-DD.jsonl`，不原地回写旧行。

原始字幕事件保留，合并时追加修订事件：

```json
{
  "type": "subtitle_revision",
  "utteranceGroupId": "utt-000123",
  "revision": 2,
  "replacesSequences": [123, 124],
  "sourceText": "合并后的完整字幕",
  "generatedAt": "2026-07-14T01:23:45+08:00"
}
```

历史读取时按 `utteranceGroupId` 只物化最新 revision。旧版没有 `type`、`utteranceGroupId` 或 revision 的 JSONL 行继续按独立字幕读取。

## Session Lifecycle

- 只持久化用户选择的模式。
- 动态端点、停顿样本、误切计数和调整冷却不写入 `settings.json`。
- 每次点击“开始字幕”从模式初始值重新学习。
- 音频设备切换或捕获重建后重置控制器。
- 诊断文件记录整个会话中的调整和分组过程。

## Diagnostics And Metrics

轻量 metrics 始终记录：

- 模式、初始值和每次调整后的端点。
- 调整时间、方向和原因。
- 当前有效样本数、P75 和目标值。
- 疑似过早切段次数。
- 字幕合并次数、组大小和跨度。
- ASR 调用次数。

每次有效停顿、quick-resume 或空闲回归判断还会追加 `endpoint_evaluation`，包含 signal、decision、当前端点、模式边界、样本数、P75、目标端点、连续 quick-resume 次数、最近 10 秒调整次数和冷却剩余时间。即使没有发生调整，也必须记录 `insufficient samples`、`cooldown`、`rate limited`、`at boundary` 等明确原因。空闲期间最多每 2 秒记录一次评估，避免逐帧刷日志，同时保留每 25ms 的端点渐进回归。设置页同步显示当前样本数、P75 和最近一次判断摘要。

只有诊断模式开启时才保存逐帧 VAD timeline 和 segment WAV。

## Acceptance Criteria

以同一批直播样本上的固定 300ms 作为基线：

- 疑似过早切段率至少下降 30%。
- `均衡`模式实际端点中位数不超过 450ms。
- `均衡`模式端点 P95 不超过上限 600ms。
- 每 10 秒最多调整 2 次。
- 字幕层合并最多 3 段、最长 12 秒，并且只合并相邻 sequence。
- 人工抽检错误合并率低于 5%。
- ASR 调用次数不能因字幕层合并增加。
- 固定值模式的分段输出与 V1.0 等价。

首轮指标用于验收和比较，不代表永久参数。真实直播样本可以驱动后续 fix 和 feature，但变更必须更新本文档和对应测试。

“疑似过早切段率”定义为每分钟音频中出现的 quick-resume 次数。同一批输入下，以该速率比较固定 300ms 和均衡自适应，避免“自适应减少总切段后，quick-resume 占静音切段比例反而升高”的失真。

离线对比命令：

```powershell
& scripts/adaptive-vad-evaluate.ps1 `
  -InputFiles @("sample-1.wav", "sample-2.wav") `
  -EnforceAutomatedGates
```

脚本会对同一批输入分别运行固定 300ms 和均衡自适应，保存两组完整诊断输出并汇总自动验收指标。错误合并率仍需结合 ASR 结果人工抽检。

## Confirmed Test Seams

实现测试必须放在以下公开边界：

1. `AdaptiveEndpointController`：输入确定性时间事件，观察有效端点、调整原因和分组决策。
2. `SpeechSegmenter`：输入动态端点提供器，观察实际切段边界；固定值行为保持不变。
3. `SettingsStore` / `AppSettingsValidator`：观察新配置默认值、强制迁移、保存加载和固定值校验。
4. `SubtitleHistoryStore`：追加原始字幕和 revision 后，读取接口只物化每组最新文本。
5. Runtime/UI smoke：观察当前动态端点、固定值控件状态、同组历史行静默替换和发布包启动。
